6. Faced Engineering Challenges & Technical Mitigation Matrix

Challenge 1 Turbopack Font Array Weight Crash

Problem: Next.js 16 Turbopack build threw 10 errors: Module not found: Can't resolve '@vercel/turbopack-next/internal/font/google/font' ... next/font/google queries have exactly one entry when font weight arrays ["400", "500"] were supplied.
Solution: Turbopack's AST font resolver requires 1:1 asset mapping; refactored font declarations to single string weight tokens (weight: "400"), eliminating resolver ambiguity and restoring instant sub-second builds.

Challenge 2 Server Component Dynamic Import Conflict

Problem: Deploying below-the-fold code splitting failed with 13 errors: ssr: false is not allowed with next/dynamic in Server Components on app/page.tsx.
Solution: In Next.js App Router, root pages default to Server Components. Injected "use client"; at line 1 of app/page.tsx, establishing a valid Client Boundary that enabled lazy-loading heavy 3D scenes and WebGL shaders without SSR conflicts.

Challenge 3 Windows PowerShell ANSI Encoding Corruption

Problem: Windows PowerShell 5.1 default Set-Content encoded files in Windows-1252 (ANSI), causing Turbopack build failure: invalid utf-8 sequence ... failed to convert rope into string and corrupted glyphs (ÃƒÂ¢Ã¢â€šÂ¬Ã¢â‚¬Å“).
Solution: Replaced default pipeline writes with programmatic .NET byte streams using New-Object System.Text.UTF8Encoding($false) without BOM, enforcing clean byte-level UTF-8 fidelity.

Challenge 4 Undefined CSS Custom Property Fallback

Problem: Active category filter buttons referenced an undefined token var(--gradient-gold) with #0b0c10 text, rendering buttons as an invisible black-on-black cloud in dark mode.
Solution: Standardized token taxonomy in styles.css, providing explicit fallback gradients (linear-gradient(135deg, #e8d2b7, #c8a882)) and high-contrast carbon ink foregrounds (#08080a).

Challenge 5 Light Mode Card Surface Inversion Defect

Problem: Switching to Light Mode converted body background to warm ivory, but cards retained hardcoded dark gradients (#14141b) while card typography inverted to dark ink, rendering text illegible.
Solution: Implemented comprehensive [data-theme="light"] overrides forcing pure #ffffff card surfaces, soft rgba(0,0,0,0.11) borders, and high-contrast charcoal typography (#0c0b0a).

Challenge 6 Execution Gating & 1–100% Telemetry State Machine

Problem: Direct URL navigations bypassed the interactive workstation hero and terminal execution flow.
Solution: Built an execution state machine in script.js gating access to dossier.html via simulated 1%–100% telemetry validation, coupled with an academic emergency bypass link (Skip Telemetry →) for grading convenience.

7. Module 6 JavaScript Syllabus Implementation Breakdown

6.1 & 6.2 Fundamentals, Scope & Data Types

Enforced 'use strict';. Block scoping applied via const (for immutable DOM references, theme dictionaries, regex patterns) and let (for mutable state such as currentThemeIndex and carousel scroll coordinates). Explicit distinction between primitives (Number, Boolean, String) and reference types (Objects, NodeLists, Arrays).

6.3 & 6.4 Numbers, Math & Control Flow

Parsed numerical data attributes via parseFloat(). Used Math.pow() and Math.min() to calculate cubic ease-out acceleration for live count-up stats. Control flow handled using defensive if...else conditionals, truthy/falsy null guards, and concise ternary operators (progress = scrollH > 0 ? (sTop / scrollH) * 100 : 0).

6.5 & 6.6 Arrays, Objects & State Dictionaries

Managed theme state with configuration objects (THEME_CONFIG). Transformed DOM NodeLists into JavaScript Arrays using Array.from() to perform real-time project filtering using .filter() and .forEach(). Client-side form validation captures field discrepancies inside an extensible error object dictionary.

6.7 & 6.8 Loops, Functions & DOM Event Listeners

Employed modern for...of loops for clean iteration over DOM elements. Modular architecture utilizes pure functions with explicit parameters and return values. DOM listeners handle 'scroll', 'click', 'submit', and mouse tracking for interactive 3D card tilt and copy-to-clipboard toast feedback.
